# file-organizer

**Sorts your Downloads folder into tidy category folders — with a preview, a journal, and one-command undo.**

Downloads folders turn into dumping grounds: installers next to invoices, screenshots
next to half-finished downloads. `file-organizer` puts every file where it belongs
and, unlike most sorting scripts, treats the operation as something you can
inspect first and reverse afterwards.

```
Downloads/                          Downloads/
├── holiday.png                     └── Sorted/
├── invoice.pdf                         ├── Images/
├── setup.exe                           │   ├── holiday.png
├── song.mp3                            │   └── screenshot.jpg
└── movie.mp4.crdownload                ├── PDF/
                                        │   └── invoice.pdf
                                        ├── Programs/
                                        │   └── setup.exe
                                        └── ...
```

## Highlights

- **Preview by default.** Nothing is moved until you pass `--apply`, and the
  preview is generated by the same planner that performs the real run.
- **Reversible.** Every move is written to an append-only journal. `undo --last`
  puts everything back, and `undo --last --apply` does it for real.
- **Conflict-aware.** Existing names are renamed (`photo (1).jpg`), skipped or
  overwritten — your choice. Identical duplicates are detected by content hash
  instead of being duplicated.
- **Respects work in progress.** Partial browser downloads (`.crdownload`,
  `.part`, `.tmp`, …), hidden files and symlinks are left untouched by default.
- **Zero runtime dependencies.** One `pip install`, no virtualenv gymnastics,
  no supply-chain surface beyond the standard library.
- **Typed and tested.** 148 automated tests, strict `mypy`, `ruff`, and a CI
  matrix across Linux, macOS and Windows on Python 3.11–3.13.

## Installation

Requires **Python 3.11 or newer**.

```bash
git clone https://github.com/ahmedk-source/file-organizer.git
cd file-organizer

python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate

pip install -e .
```

If you use [`pipx`](https://pipx.pypa.io), you can install the command globally
without touching your system Python:

```bash
pipx install .
```

Verify the installation:

```bash
file-organizer --version
```

## Quick start

```bash
# 1. See what would happen (the default, and never destructive)
file-organizer organize

# 2. Do it
file-organizer organize --apply

# 3. Changed your mind? Preview the undo, then run it
file-organizer undo --last
file-organizer undo --last --apply
```

The default source is `~/Downloads` and the default destination is a `Sorted`
folder inside it. Pass a different folder or destination when needed:

```bash
file-organizer organize ~/Desktop --destination ~/Desktop/Sorted
file-organizer organize ~/Downloads -r          # include sub-folders
file-organizer organize --on-conflict skip      # never replace anything
```

## Configuration

Configuration is optional. When present, values are merged with this precedence:

```
command-line flag  >  TOML config file  >  built-in default
```

`file-organizer.toml` is discovered in the current directory first, then as
`~/.file-organizer.toml`. Use `--config path/to/file.toml` to be explicit.

```toml
[general]
source = "~/Downloads"
destination = "Sorted"      # relative paths resolve against the source folder
recursive = false
on_conflict = "rename"      # rename | skip | overwrite
skip_hidden = true
follow_symlinks = false
default_category = "Other"

[categories]
Design = [".fig", ".sketch", ".xd"]
Ebooks = [".epub", ".mobi", ".azw3"]
Paperwork = [".pdf"]        # takes .pdf over from the built-in PDF category
```

- Extensions are case-insensitive and may be written with or without the dot.
- User assignments win over built-in ones; assigning one extension to two user
  categories is rejected as ambiguous.
- Unknown keys, wrong types and invalid category names (e.g. `CON`, `a/b`, names
  ending in a dot) fail with a clear error instead of being ignored.
- A full annotated example lives in [`examples/file-organizer.toml`](examples/file-organizer.toml).

Compound extensions are supported as well:

```toml
[categories]
Backups = [".tar.gz"]       # checked before the single .gz rule
```

## Safety model

| Protection | Behaviour |
| --- | --- |
| Dry run | `organize` and `undo` preview by default; `--apply` is required to change files. |
| Journal | One JSON Lines file per run, stored outside the source folder, `fsync`-ed after each move. |
| Undo | Reverse replay with existence checks; occupied original paths are skipped, never overwritten. |
| Partial downloads | `.crdownload`, `.part`, `.tmp`, `.opdownload`, `.aria2`-style suffixes are skipped. |
| Hidden files | Dot-files and files marked hidden on Windows are skipped unless `--keep-hidden` is used. |
| Symlinks | Skipped unless `--follow-symlinks` is used. |
| Duplicates | In `rename` mode, a byte-identical file already at the destination is not duplicated. |
| Scope | The destination tree and the journal directory are never scanned, even with `-r`. |
| Per-file errors | A locked file is reported and skipped; the rest of the run continues, exit code `1`. |

Journal locations:

| Platform | Directory |
| --- | --- |
| Windows | `%LOCALAPPDATA%\file-organizer\journal` |
| macOS | `~/Library/Application Support/file-organizer/journal` |
| Linux | `$XDG_STATE_HOME/file-organizer/journal` (fallback: `~/.local/state/...`) |

Set `FILE_ORGANIZER_STATE_DIR` to relocate the journal, which is also useful for
testing or for keeping state on another drive.

> **Heads-up:** `--on-conflict overwrite` deletes the existing destination file
> permanently — there is no backup. The default `rename` policy never loses data.

## CLI reference

```
file-organizer organize [SOURCE] [options]    preview or perform a sort
file-organizer undo [RUN_ID | --last] [options]
file-organizer history [--limit N]
file-organizer rules
```

<details>
<summary><strong>organize options</strong></summary>

| Option | Description |
| --- | --- |
| `SOURCE` | Folder to sort (default: `~/Downloads`). |
| `-d, --destination PATH` | Where category folders are created (default: `SOURCE/Sorted`). |
| `-r, --recursive` | Also sort files inside sub-folders. |
| `--on-conflict {rename,skip,overwrite}` | Conflict strategy (default: `rename`). |
| `--keep-hidden` | Include dot-files and hidden files. |
| `--follow-symlinks` | Move symlinks instead of skipping them. |
| `-c, --config PATH` | Use a specific TOML config file. |
| `--apply` / `--dry-run` | Perform the moves / preview only (default). |
| `--json` | Emit a machine-readable payload. |
| `-v, --verbose` | List every move and every skipped file. |
| `-q, --quiet` | Hide the plan; keep the final summary. |
| `--no-color` | Disable ANSI colour. |

</details>

<details>
<summary><strong>undo options</strong></summary>

| Option | Description |
| --- | --- |
| `RUN_ID` | Run id printed after `organize --apply` and listed by `history`. |
| `--last` | Use the newest run that has not been undone yet. |
| `--apply` / `--dry-run` | Perform the undo / preview only (default). |
| `--json` | Emit a machine-readable payload. |

</details>

Exit codes: `0` success, `1` some files failed, `2` invalid usage or
configuration, `130` interrupted.

## How it works

1. **Resolve settings** — merge CLI flags, the TOML file and defaults; validate
   everything before touching the filesystem.
2. **Plan** — scan the source, classify each file, resolve name collisions and
   return an immutable plan. No folders are created in this phase.
3. **Preview or execute** — `--apply` creates category folders lazily, moves
   files one by one, and journals each success. Failures are collected instead
   of aborting the run.
4. **Undo** — read the journal, replay moves in reverse, prune empty category
   folders, and mark the run as undone.

The design and its invariants are documented in
[`docs/architecture.md`](docs/architecture.md).

## Design decisions

- **Preview-first, plan/execute split.** Safety is a property of the
  architecture, not a flag that has to be remembered.
- **Journal outside the source folder.** Sorting must not create bookkeeping
  clutter in the very folder it is supposed to tidy.
- **`argparse` and the standard library only.** A small tool with no dependency
  tree is easier to audit, install and keep working for years.
- **Hash only on collision.** Conflicts are rare, so content comparison is
  deferred until a name clash actually happens.
- **Per-move `fsync`.** Slightly slower, but an interrupted run still has an
  accurate undo journal.

## Limitations

- No watch mode: the tool runs when you invoke it. Schedule it with Task
  Scheduler, cron or `launchd` if you want automation.
- `overwrite` is destructive by definition; use `rename` (the default) if you
  want to keep both versions.
- Concurrent runs against the same folder are not locked; avoid running two at
  the same time.
- The journal is local to the machine; it is not a backup system.
